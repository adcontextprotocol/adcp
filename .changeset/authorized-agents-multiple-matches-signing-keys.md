Clarify how a `signing_keys` pin combines when more than one `authorized_agents[]` entry in `adagents.json` matches the same agent (adcp#9016), for example an origin-only entry and an entry with the agent's full URL, or every entry at a Web Bot Auth signer's origin. The agent is pinned for that publisher only if every matching entry carries `signing_keys`; one matching entry with no `signing_keys` (absent or empty) leaves it unpinned. When every matching entry pins, the agent may sign with a key pinned by any of them, so the accepted keys are the union of their pins. A narrower entry never adds a restriction that another matching entry does not impose, and a verifier checking a request counts only the entries that authorize that request's scope. Pins from different publishers still intersect.
