Add definition pins so a third-party-published definition referenced by proposal commercial terms cannot silently change after commitment while `terms_digest` still verifies (#7660). Seller-authored `commercial_terms.definition_pins[]` (new `core/definition-pin.json` and `enums/definition-pin-ref-kind.json`) pin publisher-catalog format options, publisher-catalog placements, `adagents.json` collections, and data-provider signals by the lowercase-hex SHA-256 of an RFC 8785 projection of the published entry; the per-kind exclusion lists and set-array rules are published as testable vectors under `test-vectors/definition-pins/`. `refine_proposals` finalize re-verifies pins before taking a hold and reports drift as `unable` with the new `definition_changed` reason code and required `drifted_pins[]`; `accept_proposal` re-verifies before mutating and returns the new `REFERENCE_DEFINITION_CHANGED` error code (with `error-details/reference-definition-changed.json`). Adds the optional `definition_pin_probe` controller scenario and the `definition_pin_drift` storyboard gated on it. Additive on the wire (`definition_pins` is optional, `definition_changed` extends an open vocabulary); sellers emit pins and `definition_changed` only to callers negotiating AdCP 3.3 or later. `content_digest` is bare lowercase hex per the issue decision, not `sha256:`-prefixed like `terms_digest`.
