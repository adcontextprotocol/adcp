`media_buy.audience_targeting` no longer promises inline member push (#8936). Its presence now means the seller supports `audience_include` and `audience_exclude` in targeting overlays and answers discovery-only `sync_audiences` (called without `audiences`), which a declaring seller MUST do, so a buyer can always read the `audience_id` values it can target. Inline member push is declared by the `sync_audiences` pattern in the experimental `audience_targeting.supported_activation_methods`; when that field is absent, push is supported, as in 3.2. `supported_identifier_types` and `minimum_audience_size` move from `required` to an `if`/`then` that requires them only when the seller accepts inline push, so every capabilities document valid under 3.2 stays valid. A seller whose `supported_activation_methods` omits the `sync_audiences` pattern rejects, with `UNSUPPORTED_FEATURE`, a `sync_audiences` entry that carries `add` or `remove` or that would create a new audience without a `source` reference; `source` references for its declared rails still work. This lets an ad platform that can target the audiences already on an account, but cannot take a customer list, declare audience targeting without claiming member push. Generated types make both fields optional, and a strict 3.2 validator still requires them. Updated: `get_adcp_capabilities`, `sync_audiences`, the targeting guide, the 3.3 release notes and migration guide.
