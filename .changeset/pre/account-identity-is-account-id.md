Make brand identity the domain and account identity the seller's `account_id` (#8280, #8442). A brand is its `domain`, plus `brand_id` where its `brand.json` lists several brands. `brand.countries`, `currency`, `timezone`, `sandbox`, and `operator_unit` are account attributes: they no longer distinguish account identity.

- `sync_accounts`: a provisioning entry without `account` opens an account, and a retry with the same `idempotency_key` returns the original result. A provisioning entry never changes an existing account. When it matches exactly one account in the seller's account scope, on `brand` and `operator` with its attributes as filters, as the `request_account` deduplication guidance describes, the seller SHOULD return that `account_id` instead of opening another, and the exact-or-reject rules for `billing` and `payment_terms` still apply. Sellers MUST return `account_id` once the account is resolved, accept it on every account-scoped task, and never change it; a seller never issues an `account_id` it might later change. A seller that opens buyer-declared accounts through `sync_accounts` accepts settings-update entries keyed by `account_id`. Such an entry updates account attributes, `brand.countries` and `billing` included, on the same account, and the seller validates a changed attribute as it does at opening. Settings-update mode permits `brand`, `operator_unit`, `currency`, `timezone`, and `billing`. `currency`, `timezone`, and `sandbox` are set at opening: a seller MAY refuse a `currency` or `timezone` change with `UNSUPPORTED_FEATURE`, and `sandbox` never changes. A seller can review a `countries` change: the entry's result row reports `action: "unchanged"` and `status: "pending_approval"`, and the account keeps its current countries until the seller approves. `delete_missing` counts an account as included only when an entry names it by `account` or the seller returns its `account_id`.
- A natural-key `AccountRef` resolves only when exactly one of the caller's accounts matches. Each supplied attribute must equal the account's value, `countries` as a set and `operator_unit` by `id`. An omitted attribute does not filter, except `sandbox`, which defaults to `false`. Otherwise the seller returns `ACCOUNT_AMBIGUOUS` and MAY list the candidates in `error.details.candidates`.
- `brand-key.json` and `brand-ref.json`: `countries` is an account attribute, and the rule to sort country codes before computing keys is gone. `request_proposals` binds a proposal to the brand and the resolved `account_id`.

**Deprecated in 3.3, planned for removal in 4.0:** the `account.identity_updates` capability, `operator_identity` and `destination_billing_entity` on `sync_accounts`, `identity_change` and `identity_change_preview`, the `ACCOUNT_MOVED` and `ACCOUNT_IDENTITY_CONFLICT` error codes, `error-details/account-moved.json`, and `account.stable_account_id`. No wire field is removed.

Compliance: `media_buy_seller/stable_account_id` re-sends its provisioning entry and checks, as an advisory SHOULD, that the seller returns the same `account_id`. `media_buy_seller/account_timezone_buyer_selected` drops the re-sync reconnect phases.

Training agent: a settings-update entry that changes an account attribute returns `UNSUPPORTED_FEATURE`, and one that carries `operator` returns `INVALID_REQUEST`.
