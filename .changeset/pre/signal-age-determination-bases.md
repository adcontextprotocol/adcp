Signals declare their age determination basis (#8145). Adds an optional `age_determination_bases` array (`verified`, `declared`, `inferred`; `minItems: 1`, `uniqueItems`) to `signal-listing`, `signal-definition`, and `signal-definition-enrichment`, as a sibling of `demographic_predicate`, plus the `get_signals` `fields` projection value. It lists the user-level bases by which a signal's members' ages were established, and is valid only when `demographic_predicate.age` is present. Authoritative on product-scoped listings; for `data_provider` and `signal_source` refs a projected value MUST match the referenced definition. Absent means no basis claim, and a buyer whose request names `accepted_bases` MUST NOT treat that signal as satisfying the age predicate. A signal listing satisfies a requested age predicate with `accepted_bases` only when its age range is within the request and every one of its bases is in `accepted_bases`. Population estimates stay in `audience_evidence`.

This is **stable, not experimental** (`x-added-in: "3.3.0"`): a deliberate exception to the single-adopter rule, because the field completes a stable basis vocabulary already on the wire as `accepted_bases`, `supported_bases`, and `applied_bases`. On AdCP 3.2, carry the value as `ext.adcp.age_determination_bases` on the signal-listing entry (the AdCP-owned `ext.adcp` namespace, as with `ext.adcp.opportunity`), so migrating to 3.3 is a rename. When gender targeting (#7925) graduates it will need an equivalent disclosure; the enum is not generalized now.
