compliance(media-buy): grade inline creative paths on what each seller actually publishes, and give the provenance scenarios complete seeded products.

`inline_creatives_without_sync` required a product carrying canonical `format_options[]` with a stable `format_option_id`, and treated the legacy `format_ids[]` path as `optional`. Canonical-only sellers with unnamed options, and legacy-only sellers, therefore failed a representation AdCP never required them to publish — `core/product.json` requires `format_ids`, `format_options`, or both, not both (adcp-client#3268).

The storyboard now has four execution paths. One canonical discovery captures the product, the pricing option, the canonical `format_kind` and the whole first `format_options[]` declaration from a single `get_products` response; three mutually exclusive canonical paths then read that captured declaration to decide which selector shape the seller published:

- **product-local option** — `format_option_refs[]` with `scope: "product"`
- **publisher-catalog option** — `format_option_refs[]` with `scope: "publisher"`, carrying the complete `{publisher_domain, format_option_id}` pair `core/product-format-declaration.json` makes such an option addressable by
- **no stable `format_option_id`** — no selector at all, `format_kind` alone

The legacy `format_ids[]` path keeps its own discovery and runs independently. Capturing the declaration whole is what makes this safe: `format_option_id` and `publisher_domain` are both optional on a declaration, and a capture that does not resolve fails its step and discards every other capture with it, so capturing either one on its own would make it a precondition for the path that must not require it. The `scope` field is the only part of the ref no response carries; it comes from a storyboard-root constant injected with `context_inputs`, which deep-clones the request before writing so the captured declaration is never mutated.

Because every canonical gate and every canonical buy now come from one response, a seller whose brief-mode results reorder — or whose canonical shape differs between calls — is never failed for it. Execution phases are not optional, so once a representation was actually captured, inline create, update and readback on it must work. A closing `assert_contribution` fails any run in which no path completed.

A publisher-catalog-backed product previously received a `scope: "product"` ref that omitted `publisher_domain`. `core/format-option-ref.json`'s product-local branch forbids `publisher_domain` outright, so that ref was unresolvable and a conformant seller had to reject it — failing the storyboard for being right. It is now graded on its own path.

Make the three provenance storyboards' seeded products complete: they were missing the schema-required `publisher_properties` and `reporting_capabilities` and declared no format at all, so `core/product.json` rejected them outright and the creative probes referenced a format nothing seeded (adcp-client#3269). Their CPM pricing option also carried a `rate` field the schema ignores, so the product advertised no price. They now declare `fixed_price` and an `image` format option matching their creative probes.

The canonical discovery probe additionally checks `products[0].format_options[0].format_kind` is `image`. `filters.format_kinds` narrows to products that *accept* a kind and says nothing about declaration order, so a conformant multi-kind product can lead with another kind; capturing that declaration would otherwise ship this fixture's 300x250 image asset under the wrong `format_kind` for a seller to correctly reject, on a non-optional phase. The check **detects** that mismatch rather than selecting a matching declaration — a red there closes all three canonical gates, so a canonical-only seller leading with another kind is not graded on any canonical path and the closing `assert_contribution` fails the run.

Applicability, which predates this change: the buyer submits one fixed 300x250 image creative, and every path reads `products[0]` of its own response and that product's first format declaration. Answer this brief with a first product whose `pricing_options[0]` is fixed-price and whose `format_options[0]` — or `format_ids[0]` on the legacy path — accepts a 300x250 image. Selecting a compatible declaration by kind or dimensions regardless of array order would need an order-independent selector the storyboard grammar does not have; that is a general limitation, not addressed here.

Tooling: `scripts/lint-storyboard-sample-request-schema.cjs` synthesized `{}` for a `$context.*` placeholder whose target is a discriminated union written as `{ type, discriminator, oneOf }` (`core/format-option-ref.json`), because the shape lives on the branches rather than the root — ajv then reported the `scope` tag as missing. `placeholderFor`'s object arm now takes the shape from the first object branch when the root carries no `properties`. The allowlist is unchanged.

Reading the report: both discovery phases are `optional`, and a seller publishing one representation **will see the other's discovery step go red**. That is expected and takes no action — those steps do not gate the run. A red step inside an execution phase means the opposite: that representation was advertised, and inline create, update and readback on it must work. The closing `assert_contribution` is the only coverage gate.

Adopters: the legacy path is now graded. A seller whose discovered product advertises `format_ids[]` will newly fail this storyboard where the previously-`optional` legacy phase did not grade it. Either fix the legacy inline path, or stop projecting to `format_ids[]` and advertise `format_options[]` alone — `format_ids` is deprecated in 3.2 and removed in 4.0, and a canonical-only product stands the legacy path down cleanly. Note the legacy discovery probe selects `products[0]` on `is_fixed_price` alone, so a dual-emitting seller whose first fixed-price product is not an image surface will have that product's `format_ids[0]` bought against a 300x250 image creative; rank a product that accepts the inline image creative first for this brief.

Phase ids changed, so any diagnostics keyed on them need updating. `verify_replacement` is gone and the readback steps moved into their path phases; `canonical_format_inline_path` is replaced by `canonical_product_scoped_inline_path`, `canonical_publisher_scoped_inline_path` and `canonical_unnamed_option_inline_path`, and `get_products_canonical_format` moved into the new `canonical_format_discovery`. The other new ids are `legacy_format_discovery` and `verify_format_coverage`.

Runner floor: the canonical paths gate on `skip_if` expressions that read into a captured object, and on a runner whose `skip_if` grammar cannot evaluate captured context every canonical path would execute rather than exactly one. Verified end-to-end on the `@adcp/sdk` 14.0.0-rc.53 this branch pins, and reported green on 15.9.2. No claim is made here about which earlier release first carried the grammar — run the fixture regressions against any older runner before pointing it at this bundle.
