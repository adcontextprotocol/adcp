Grade inline creative format paths against the representation the seller actually publishes, and give the provenance scenarios seeded products and formats their probes can resolve.

`inline_creatives_without_sync` previously required every seller to satisfy both the canonical `format_options[]` path and the legacy `format_ids[]` path, so canonical-only and legacy-only sellers failed on a representation they are not required to publish. There are three routes, not two: the named canonical path (`format_option_refs[]`), an unnamed canonical path for products whose `format_options[]` entries publish no selectable `format_option_id`, and the legacy `format_ids[]` path. The unnamed route omits every package selector and carries `format_kind` alone on the creative — `creative-asset.json`'s 3.1 arm requires only `format_kind`, `format_option_ref` is "optional when `format_kind` alone routes the creative to a single declaration", and `package-request.json` requires only `product_id` / `budget` / `pricing_option_id`. It is captured by its own discovery probe (captures are per step, not per key, so folding it into the named probe would discard it for exactly the sellers it serves) and is gated twice so a selector-less purchase can never reach a named catalog: a phase-level `skip_if` on runners that read context, and a `field_absent` check on `products[0].format_options[0].format_option_id` in its own discovery probe for runners that do not — a named product fails that probe, so its captures are never promoted and the route cannot fire. This matters because a product with several `format_options[]` entries sharing one `format_kind` genuinely requires a `format_option_ref`, and a correct seller rejects a package without one. A seller publishing `format_option_id` is therefore graded once, on the named route. This closes the last applicability gap: `format_option_id` is a SHOULD, and a product that omits it is no longer failed.

Each route opens with its own optional discovery phase that captures the product, the pricing option, and that path's format representation from one `get_products` response — the same response the path then buys from, so the signal that decides whether a path runs and the product it buys are one observation rather than two that can disagree. A representation the product does not advertise does not resolve, and the path skips instead of projecting one.

**What this does not relax.** If a path's discovery observes a representation, that path is graded on it. Both path phases are non-optional, so a create, update, or replacement-readback failure on an observed path fails the storyboard even when the other path passes — unchanged from the previous behavior. A closing `assert_contribution` requires at least one path to reach the replacement readback and see the replacement creative on `creative_approvals`, so a run in which both paths skip still cannot pass.

**Runner compatibility.** Each path phase carries `skip_if` keyed to its own discovery capture (the unnamed canonical route additionally stands down when the named route is available). Runners whose `skip_if` grammar is `test_kit`-only ignore it and reach the same outcome, because there every step in an ungated path skips on the unresolved context and an all-skipped non-optional phase still grades `passed`. Runners that evaluate `skip_if` against captured context need it: on those, an all-skipped non-optional phase grades `passed: false` and fails the storyboard, so without the guard a conformant canonical-only or legacy-only seller would fail. Verified green on 9.6.2, 15.8.1, and 15.9.2 for canonical-only, legacy-only, dual-emission, and reordered discovery responses, and still red for a seller advertising a representation it mishandles. The guard is load-bearing on 15.x: with it stripped, canonical-only and legacy-only sellers fail there.

**Known reporting wart, pending an SDK release.** A conformant canonical-only or legacy-only seller leaves one deliberately non-gating failed step — the optional discovery probe for the representation it does not publish. The runner and the `adcp` CLI both treat the run as green (`overall_passed: true`, exit 0), but `--format junit` emits `<testsuites failures="1">` against `<testsuite failures="0">`, so a pipeline gating on the JUnit aggregate rather than the exit code goes red. The fix is in `@adcp/sdk` (an additive `StoryboardStepResult.counts_toward_failure: false` on deliberately-optional failures; required OAuth and step assertions keep failing CI) and lands with that SDK release — no storyboard change can avoid it. Gate on the CLI exit code until then.

**Scope of the gate, and a known limit.** Each path is gated on `products[0]` of its own discovery call. A representation published only on other products is not graded unless the first product matched to this brief carries it, so rank a product carrying the representation first for this brief or publish it on every product that matches. Both discovery calls send the same brief and filters and sellers are expected to answer them consistently, but nothing cross-checks that: a seller that withholds a representation from the call that would gate it is simply not graded on that path. No capability field declares which format representations a seller emits, so the storyboard cannot verify the claim today; closing this needs either such a capability or a runner that can gate on more than `products[0]`.

Two further limits are deliberate. **A schema-invalid discovery response takes its whole path out of grading.** Captures are applied per step, not per key: when one fails the runner discards all of that step's captures, so the gate sees nothing and skips the path, and because the discovery phase is optional its own `response_schema` failure is swallowed too. An advertised-but-invalid path can therefore disappear while the other path carries the run. This is the price of letting a genuinely absent representation skip without failing a conformant seller — the two are indistinguishable from the captures alone. `get_products` schema conformance is still graded on its own via `full_sales_flow`.

The three provenance scenarios (`provenance_enforcement`, `provenance_audit_observation`, `provenance_truth_of_claim`) seeded products that omitted the required `publisher_properties`, `reporting_capabilities`, and format declarations, and their creative probes referenced `display_300x250` on `your-platform.example.com`, which nothing seeded — so a seller that correctly rejects an unknown format failed the scenario for being right. Each now seeds a schema-valid product plus a fixture-local legacy format declaring the `image`, `headline`, and `click_url` assets its probes submit, and every probe references that seeded format. The fixed-CPM pricing option also moves from `rate` to `fixed_price`; `rate` validated only because the pricing option allows additional properties, and the option was being read as auction-based.

**Action required for seeding sellers.** These three scenarios now declare a `fixtures.creative_formats` block, so `seed_creative_format` joins `seed_product` and `seed_pricing_option` as a required `comply_test_controller` scenario for them. A seller whose `list_scenarios` does not advertise `seed_creative_format` will see all three grade `not_applicable` (`fixture_seed_unsupported`) instead of running — the runner skips the whole storyboard rather than seeding partially. Advertise `seed_creative_format` to keep coverage.
