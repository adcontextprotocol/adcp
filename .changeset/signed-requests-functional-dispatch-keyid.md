Stop signed functional storyboard requests from exhausting the per-keyid cap that the signed-requests `rate_abuse` vector grades (adcp#8877). Functional dispatch in `test-kits/signed-requests-runner.yaml` signed with `test-ed25519-2026`, the same keyid vector 020-rate-abuse caps at 100 for the test counterparty, so a full compliance run could hit the cap before the signed-requests vectors started and fail them with `request_signature_rate_abuse`. Functional dispatch now signs with a dedicated `test-functional-2026` Ed25519 key that no conformance vector uses, published in the request-signing `keys.json` and declared in `runner_signing_keys`. The `rate_abuse` block now states that agents MAY lower the per-keyid cap to the grading target for the vector 020 keyid (`test-ed25519-2026`) only, and MUST NOT apply the lowered cap to the functional-dispatch keyid. Sellers that register the runner signing keys individually rather than loading the published `keys.json` must add `test-functional-2026` to their test counterparty. Sellers that configure one global per-keyid cap on their replay store (as the SDK reference stores take, e.g. `maxEntriesPerKeyid: 100`) must scope the lowered cap to `test-ed25519-2026`, for example with a keyid-aware wrapper, or functional storyboards hit the cap on `test-functional-2026` instead.
