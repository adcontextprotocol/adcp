Reporting subscriptions (experimental, `media_buy.reporting_subscriptions`): beta.5 coverage fixes. One of them changes the coverage rule, and both SDKs must adopt it and pass the new vectors.

- **Coverage rule change, which SDKs must adopt: `package_ids` exceptions compose.** Before, a period was removed only when a single `package_ids` exception entry named every package that resolves the offering and is owed that period. Two separate entries that together named every owing package did not remove it, so a buy whose packages had each been excluded by separate entries still owed the period. Now a period is removed when the union of the packages named by the `package_ids` exceptions in effect for it covers every package that resolves the offering and is owed that period. An entry is in effect for a period when its `[from, until)` contains the period's start and, when it has `offering_id`, that offering matches. It doesn't matter whether one entry names every package or several entries each name some. `added_at` composes as before: a package added later counts only for the periods it is owed. In-place membership and the version scoping of `excluded_by_buyer` are unchanged. `core/reporting-subscription.json` `coverage`, the `package_ids` description in `core/reporting-subscription-coverage.json`, `reason-codes.json` (the `exception` rule and `excluded:offering_unsupported`; no code changes), and the reference model all say so. No existing vector changes. New vectors: `package-exclusions-together-name-every-resolving-package`, `package-exclusions-together-name-all-but-one-resolving-package`, `staggered-package-exclusions-remove-periods-once-both-apply`, and `package-exclusions-compose-with-a-package-added-later`. Until the SDKs adopt the rule, three of them (all but the all-but-one case) fail through both SDKs.
- **Reference-model fix, which SDKs already follow: billing stub at an account timezone change.** The `cutover` rule applies to account timezone changes "including on billing offerings, where the stub rule above applies", and `timezone_cutovers` says the same. The reference model never emitted that stub. It now owes, on a billing offering, one stub period `[effective_at, first new-timezone boundary)` with `stub: true` when `effective_at` is not already a new-timezone boundary, and no stub when it is. The spec text is unchanged. New vectors: `billing-account-timezone-change-mid-month-owes-a-stub`, `billing-account-timezone-change-eastward-owes-a-stub-of-most-of-a-month`, and `billing-account-timezone-change-on-a-shared-boundary-owes-no-stub`. Both SDKs already pass them.
- The differential harness generator (`tests/interop/differential/generate.cjs`) now puts billing feeds on `account_timezone`, including monthly ones, under timezone changes, sometimes to a zone with the same offset. It also writes staggered `package_ids` entries for one buy. Two new properties in `tests/reporting-subscription-coverage-properties.test.cjs` cover composition and billing contiguity across a timezone change.
