Governance (3.4): declare `plans[].human_override` on `sync_plans` and state the human-review downgrade rule (#9068).

- **Schema.** The `sync_plans` plan item declares `human_override`: an object with `reason` (non-empty string) and `approver` (string), both required, an optional `approved_at` (date-time), and open to additional members. It is part of the `plan_hash` preimage, as the specification already said.
- **Rule.** The campaign governance specification ("Human review required") now states normatively that a re-sync that would change a stored plan from human review required to not required MUST carry `human_override`, and that without it the governance agent MUST reject the sync with `VALIDATION_ERROR` and leave the plan unchanged. The rule follows the stored state: it applies whether the re-sync sends `false` or omits the flag, and whether the stored `true` was set by the caller or derived from policy. A governance agent MAY apply stricter checks (minimum reason length, `approved_at` freshness, `approver` as an email address or an authenticated identity). `human_override` never permits `false` while a triggering policy is present. The governance agent stores the artifact and keeps it when a later re-sync omits it; `plan_hash` is still computed over the plan as supplied, so a buyer SHOULD resend `human_override` on later re-syncs while the flag stays lowered.
- **Docs and compliance.** The `sync_plans` task page lists the field and the rejected downgrade under `VALIDATION_ERROR`, the Annex III page points at the normative rule, and the new `governance/human_review_downgrade` storyboard checks that lowering the flag without `human_override` (by omission or by `false`) is rejected and that the same re-sync with it succeeds.

**Migration note.** `sync-plans-request.json` is `x-status: experimental`. The declaration narrows what validates against 3.2.11 and 3.3: the plan item was open and `human_override` undeclared, so any value validated. A string (for example `"approved by legal"`), a `reason`-only object, an object without `approver`, and an empty `reason` no longer validate. This documents existing behaviour rather than changing it: "reason + approver" is the only shape AdCP has ever described (3.0 release notes, the Annex III obligations page), and the reference governance agent has required that shape, and rejected every other one, since 3.0. Before: `"human_override": "approved by legal"`. After: `"human_override": { "reason": "Campaign narrowed to brand awareness; no housing offers remain.", "approver": "legal@pinnacle.example" }`.
