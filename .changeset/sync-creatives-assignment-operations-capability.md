Sellers declare which `sync_creatives` `assignment_operations` they accept, and a refusal recommends `replace` only where the seller accepts it (adcp#8933). `assign`, `unassign` and `replace` have existed since 3.2 and 3.3 adds `merge`, but only `merge` had a capability flag, so a buyer learned what a seller accepted by being refused. Live creative updates made this matter: `CREATIVE_LIVE_UPDATE_UNSUPPORTED` told buyers to swap in a new creative with a `replace` that the seller might refuse too.

- **`creative.assignment_operations`.** New optional array on `get_adcp_capabilities`, any of `assign`, `unassign`, `replace` and `merge`. The list is exact: the agent accepts every listed operation and rejects any other with `UNSUPPORTED_FEATURE`, applying nothing. Buyers MUST NOT send an operation that is not listed. Absent from a response served at 3.3 or later, the agent accepts none and buyers MUST NOT send `assignment_operations`. A response served at 3.2 cannot carry the field, so there its absence declares nothing.
- **Live updates require `replace`.** An agent that declares the experimental `creative.live_updates` MUST list `replace`; the schema enforces it. The `CREATIVE_LIVE_UPDATE_UNSUPPORTED` recovery, suggestion and details say so. The `CREATIVE_MERGE_REJECTED` recovery and the `content_mismatch` and `not_supported` merge rejection reasons name `replace` only where the seller lists it.
- **Compact buys require `assign`.** A seller that exposes `buy_products` or `accept_proposal` and declares `creative.has_creative_library: true` MUST list `assign` in a capabilities response served at 3.3 or later, because the compact lifecycle assigns creatives only through `assignment_operations`. A verifier constraint records it; the schema cannot, because the antecedent fields are 3.2 fields.
- **`merge`.** Listing `merge` requires `has_creative_library: true` and `stable_creative_ids: true`, as `supports_assignment_merge` does. That flag stays for compatibility; when it is `true`, the list MUST include `merge` (schema-enforced), and a seller that lists `merge` SHOULD set it. The `merge` verifier capability gate now names the list.
- **Suggestions name only what the agent accepts.** `core/error.json` `suggestion`: a suggestion, and the recovery a correctable code documents, SHOULD name only operations and fields the agent declares it accepts or the schema requires it to accept.
- **Conformance.** `media_buy_seller/assignment_replace_transfers_settings` runs only against sellers that list `assign` and `replace`. `media_buy_seller/compact_direct_buy_lifecycle` checks that a seller with a creative library lists `assign`, and `sales-broadcast-tv` checks that the seller lists `assign` before sending one. The reference training agent lists `assign`, `unassign` and `replace` on its media-buy routes, refuses `merge` and every operation on its creative-only routes, and words its live-update refusal from its own list.

Additive for schemas: a new optional capability field and description changes. Behaviorally, a 3.3 seller that accepts `assignment_operations` must now list them, or 3.3 buyers stop sending them.
