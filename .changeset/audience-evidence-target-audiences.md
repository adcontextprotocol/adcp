Add an experimental `target_audiences[]` list (`media_buy.audience_evidence_targets`, #8125) so a buyer can name the audience it wants evidence for. It is a sibling of `audience_evidence_requirements` on `get_products` `filters` (`core/product-filters.json`) and on `create_media_buy` packages (`media-buy/package-request.json`), and requires that requirements object, whose `requirement_mode`, `evidence_presence` and admissibility constraints govern it. The closed `core/audience-evidence-requirements.json` and `core/product-audience-evidence-requirements.json` schemas are unchanged, and the closed `buy_products` purchase schemas and `list_products` `offer_filters` gain the field in 4.0 (new registry check `purchase_target_audiences_required_in_4_0`). Each item (`core/audience-evidence-target.json`) has an `audience`, a `relationship` and a `minimum_value`. A product satisfies a target only through an admissible `audience_evidence` item with an exactly matching audience, the same relationship and a value at or above the minimum. Targets combine with AND, `preferred` ranks and explains through `audience_evidence_selections`, `required` excludes, and a target is never a targeting predicate. Adds `enums/audience-evidence-relationship.json` for the target's `relationship`, with the same values as the inline enum on `audience_evidence.relationship`, which is unchanged.
