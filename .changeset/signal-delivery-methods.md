Add experimental provider-initiated signal delivery to agent destinations (`signals.delivery_methods`, #6552). Signal agents declare `signals.delivery_methods[]` on `get_adcp_capabilities` (new `core/signal-delivery-method.json`, same pattern vocabulary as audience activation methods, read from the send side; `tmp_identity_match` excluded). `activate_signal` agent destinations accept an optional `delivery_method` pin; with no pattern+vendor intersection the destination fails with `UNSUPPORTED_FEATURE`. Agent deployments gain `delivery_state` (`awaiting_read` / `delivered` / `failed`, new `enums/signal-delivery-state.json`), a `delivery` descriptor shaped like `core/audience-source.json`, `delivery_error`, and optional match outcome (`match_status` reusing `audience-status`, `matched_count`, `effective_match_rate`). Signal agents that declare the capability MUST deliver only over a pattern+vendor intersection with the destination's declared methods; a pin sent to an agent that does not list it is rejected with `UNSUPPORTED_FEATURE`, and receiver fields not yet established fail the destination with `ACCOUNT_SETUP_REQUIRED`. Additive; experimental under the new `signals.delivery_methods` feature id.
