Add an experimental `extend_hold` action to `refine_proposals` (feature id `media_buy.hold_extension`, #8086; single adopter: Availnet, a creator marketplace). It lengthens a committed hold without lapsing and re-finalizing: it MUST target a committed, unexpired proposal, accepts only `proposal_id` and `action`, and returns a new committed successor (`parent_proposal_id` is the source, `commercial_terms` and `terms_digest` unchanged, later `expires_at`) reported as the existing `finalized` outcome. The hold transfers to the successor and the source can no longer be accepted (`INVALID_STATE`); a failed extension returns `unable` with `hold_unavailable` (siblings `batch_aborted`) and leaves the source and its hold unchanged. A batch containing `extend_hold` contains only `extend_hold` entries and is atomic, like finalize. Exact retries replay. Sellers declare `media_buy.proposal_refinement.hold_extension: true` and list the feature id in `experimental_features`; buyers MUST NOT send `extend_hold` otherwise, and sellers that do not declare it fail the unknown action with `VALIDATION_ERROR`. Counts and maximum durations remain seller policy.
