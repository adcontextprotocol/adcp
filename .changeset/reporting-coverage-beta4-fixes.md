Reporting subscriptions (experimental, `media_buy.reporting_subscriptions`): beta.4 coverage fixes. Two of them change the coverage rule, and both SDKs must adopt them and pass the new vectors.

- **Coverage rule change: per-package `added_at`.** `get_media_buys` `packages[].added_at` (optional, date-time) records when a package was added to a buy after its `confirmed_at`. It is that package's own `confirmed_at`: the package is owed the periods that end after the later of the buy's `confirmed_at` and its `added_at`, so the period containing `added_at` is owed in full, and it resolves subscription selectors at the later of the version's `accepted_at` and that instant, from the `reporting_delivery_offering_ids` fixed then. The buy owes a period of an offering when at least one package resolving it is owed that period, and a `package_ids` exception removes a period when it names every package that resolves the offering and is owed the period, so packages added and later excluded compose. Adding a package is never a cutover. Absent `added_at` means the package was part of the buy at confirmation, so existing data reads as before; a value at or before `confirmed_at` has no effect. Sellers advertising the feature MUST include it on every package added after confirmation. Buyer SDKs that resolved a later package with the buy over-owed. Reason code `before_package_added` (rule `confirmation`) is added to `reason-codes.json`.
- **Coverage rule change: a grant reduced without `get_reporting_status` is a loss of authority.** It ends reporting authority at the reduction, exactly like a revocation: the seller lists the account in `accounts_unauthorized[]` with `unauthorized_at` set to the reduction, delivers nothing for periods ending after it, withholds owed periods that ended by then, and refuses `get_reporting_status` for the account with `SCOPE_INSUFFICIENT`. Adding `get_reporting_status` back is a re-grant (chain, `regranted_at`, gaps, `backfill_on_regrant`, admission). A reduced grant that still lists `get_reporting_status` (the wind-down grant) is not a loss of authority. In the vectors, a reduction ends a `grants[]` interval like a revocation.
- **Error code for the `account_id` key rule.** `error-codes.json` adds the seller code `SUBSCRIPTIONS_REQUIRE_ACCOUNT_ID_KEY` (recovery `correctable`; TypeScript `PlatformConfigError`, Python `ReliableReportingConfigurationError`), raised when a managed-delivery offering's `reporting_profile.primary_keys` lacks `account_id` or its fetched row schema doesn't declare `account_id` as a required string. It replaces the TypeScript fallback to `PLATFORM_CONFIG_INVALID`. The new `offering-checks.json` vectors, with `scripts/reference/reporting-coverage/offering-checks.cjs`, pin it and `SUBSCRIPTIONS_REQUIRE_STANDARD_DIMENSIONS`.
- **Schema-enforced durations.** `core/reporting-schedule.json` and `core/reporting-schedule-offering.json` now reject a `period_duration` with both a non-zero date component and a non-zero time component (`P1DT12H`) under `account_timezone`, `source_timezone`, or `billing_cycle`, exactly what the period rule already refused. `P1DT0H` and `P0DT12H` stay valid, and `utc` still accepts mixed durations. The vector `local-duration-cannot-mix-date-and-time` is now `wire_valid: false`.
- **Codegen-safe `destination_overrides[]`.** The item's rules (exactly one of `account_ids` and `operator_domains`; `{account_id}` in `path_template` when an entry can select more than one account) move from sibling `anyOf`, `not`, and `allOf` into one `if`/`then`/`else`, so json-schema-to-typescript and datamodel-codegen generate one object type with every field instead of empty objects. Validation is unchanged; no wire change.
- **Full tzdata in the reference model.** `scripts/reference/reporting-coverage/tzdata.json` now carries the whole default zic build of IANA tzdata 2026f (344 zones, 253 links, 135 rule sets) instead of 11 zones, so the model evaluates any zone. Each zone is checked against zic(8) for 1970 through 2040 through a per-zone digest. `tz.cjs` now reads a Zone's wall-clock UNTIL as zic does when a rule transition falls on the same instant (America/Vancouver's 2026 change), which 42 zones outside the old set needed.
- **New vectors.** `package-added-mid-period-is-owed-from-the-period-containing-added-at`, `package-added-before-confirmation-is-owed-from-confirmed-at`, `package-added-on-a-period-boundary`, `package-added-then-removed-composes-with-package-exclusions`, `package-added-in-the-25-hour-day-australia-sydney`, `package-added-later-resolves-at-its-added-at`, `grant-reduced-without-get-reporting-status-is-a-loss-of-authority`, `get-reporting-status-restored-to-a-reduced-grant-is-a-re-grant`, `grant-reduced-but-still-listing-get-reporting-status-keeps-coverage`, `pacific-auckland-spring-forward-23-hour-day`, `pacific-chatham-hourly-across-a-45-minute-offset-dst-start`, `america-mexico-city-no-dst-after-the-2022-rule-change`, `america-mexico-city-last-fall-back-in-2022`, `asia-kolkata-half-hour-offset-local-days`, and `utc-alignment-accepts-a-mixed-duration`.
- The training agent emits `added_at` on packages added to a confirmed buy, computes their coverage from it, and treats a `reduce_grant` without `get_reporting_status` as a loss of authority listed in `accounts_unauthorized[]`, with restoration as a re-grant.
