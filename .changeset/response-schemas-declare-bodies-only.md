Task response schemas declare only bodies. The protocol envelope owns every envelope field, `status` included, and the schema build generates each task's wire response as a disjoint union of the task's status bodies.

- A task declares one body per envelope status, and the file name carries the status: `<task>-response.json` (completed), `<task>-async-response-<status>.json` (submitted, working, input-required), `<task>-rejected.json` and `<task>-failed.json`. Each body serves only that status and never tests `status`. Bodies stay open; where a status excludes a field, the body says so with `not`.
- The build publishes `/schemas/<protocol>/<task>-wire-response.json` for every task: a `oneOf` discriminated by `status`, one branch per status that has a body, each requiring `status`, pinning it to its own value and composing that body. The manifest's `response_schema`, the MCP projection's `outputSchema`, and the storyboards of the tasks whose `-response.json` changed name the wire response.
- Inline status branches and status conditions move to status bodies, and `-response.json` keeps its `$id` and validates only a completed response. New submitted bodies: `sync_audiences` and `preview_creative`. New failed bodies: the operation-level error body of each task that has one, the compact failed bodies, `get_reporting_status`'s failure kinds, `request_account` and `list_account_changes` (which require `adcp_error`), `get_products`, `get_signals`, `get_principal` and `sync_principal`. New rejected bodies: `get_principal` and `sync_principal`. The fields that `get_products`' completed and rejected bodies share are declared once, in `media-buy/get-products-shared-properties.json`.
- Where a task's `-response.json` and its `-async-response-submitted.json` disagreed about a submitted response, the submitted body takes the tool response's rules: the fields it excluded and the fields it declared.
- Body schemas no longer declare `status` or mirror `context`; the envelope declares both.

Validation changes, all from dispatching on `status`. A tool response with a status its task has no body for (`canceled`, `auth-required` and `unknown` for every task, and others for tasks without that body) is rejected; the old `-response.json` accepted it whenever the completed fields were present. A response is validated against its own status's body, so a failed or submitted response carrying only success fields is rejected, and a working or input-required payload is accepted as the tool response it already was on the async channel. The standalone submitted payloads of `build_creative`, `control_media_buy`, `create_media_buy`, `update_media_buy`, `buy_products`, `accept_proposal`, `sync_catalogs`, `sync_creatives`, `refine_proposals`, `request_proposals` and `decline_proposals` reject what their tool response already rejected. The composition test lists each change by task and status. Minor, not patch: the release publishes new schema identities (the wire responses and the new status bodies), and the manifest's `response_schema` changes to the wire response.
