Every task response schema now accepts and declares the `adcp_version` echo that `versioning.mdx` requires on every response (#8518). Closed responses that rejected it now declare `adcp_version` as a `$ref` to `core/version-envelope.json#/properties/adcp_version`: `control_media_buy`, `decline_proposals`, `get_media_buy_issue`, `report_media_buy_issue`, `list_collections`, `list_proposals`, and `media-buy-commitment-response.json`, which covers `buy_products` and `accept_proposal`. Open status payloads that tolerated it without declaring it now compose `core/version-envelope.json` via root `allOf`: `core/compact-task-working.json`, `core/compact-task-input-required.json`, and the non-compact `*-async-response-{submitted,working,input-required}` payloads. The `list_products` echo drops its `x-added-in: 3.3.0` marker because the echo is backported to 3.2.x. A conforming seller already emits the echo, so no seller becomes non-conformant; a malformed echo (for example `"3.3.0"`) now fails validation where these schemas declare it. `tests/response-version-echo.test.cjs` enumerates every tool's response and async status schemas from the tool registry and fails when one rejects the echo, leaves it undeclared, or declares it with a different shape.
