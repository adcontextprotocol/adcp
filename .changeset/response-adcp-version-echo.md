The 3.2 task response schemas now accept the `adcp_version` echo that `versioning.mdx` already requires on every response (#8518). A strict 3.2 validator rejected the echo on the closed compact responses, so it rejected every spec-conforming 3.2 seller. `list_products`, `control_media_buy`, `decline_proposals` and `media-buy-commitment-response.json` (which covers `buy_products` and `accept_proposal`) now declare `adcp_version` on every closed arm as a `$ref` to `core/version-envelope.json#/properties/adcp_version`. The open async status payloads now compose `core/version-envelope.json` via root `allOf`, so they declare the echo they previously accepted only as an unknown key. Those payloads are `core/compact-task-working.json`, `core/compact-task-input-required.json`, and the non-compact `*-async-response-{submitted,working,input-required}` schemas. The failure arms of `get_reporting_status` reference the envelope in place of local `{ "type": "string" }` stubs. Validation there is unchanged, because the root already composed the envelope. This patch adds no new contract: the echo is an existing MUST and conforming sellers already send it. `tests/response-version-echo.test.cjs` fails if any task response or async status schema rejects the echo, leaves it undeclared, or declares it with a different shape.
