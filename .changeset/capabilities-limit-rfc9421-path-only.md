Bound the `get_adcp_capabilities` response by structure and keep `MAX_CAPABILITIES_BYTES` as the safety net (#8198). Every array, string, and keyed map in the response schema, and in every shared schema it references, now has a limit. Fields new in 3.3 and experimental fields enforce it with `maxItems`, `maxLength`, or `maxProperties`. Fields that were stable before 3.3 carry it as `x-max-items-4.0`, `x-max-length-4.0`, or `x-max-properties-4.0`, a SHOULD through 3.x that 4.0 turns into the keyword, registered as `capabilities_structural_bounds_required_in_4_0`. No schema-valid 3.2 document becomes invalid. `scripts/capabilities-structural-bounds.cjs` computes the worst-case schema-valid document (89,611,443 bytes, counting declared members only). Documentation states that the 64 KiB budget binds only the deprecated RFC 9421 discovery path, which gains no request field and stays as written through 3.x, that the Web Bot Auth key directory (DR-0023) never fetches capabilities, that no new path reads key material or a key pointer from capabilities, and that agents with large creative catalogs adopt Web Bot Auth or keep capabilities under the limit.
