`get_account_requests` returns the caller's [account requests](/docs/accounts/tasks/request_account): where each one stands, whose turn it is, and the account it resolved to. It is side-effect free and only ever returns the caller's own requests.

<Note>
**Experimental.** Part of the account requests surface (`account.requests`, [#8280](https://github.com/adcontextprotocol/adcp/issues/8280)), new in AdCP 3.3. It may change between 3.x releases with at least 6 weeks' notice. See [experimental status](/docs/reference/experimental-status).
</Note>

**Request schema:** [`account/get-account-requests-request.json`](https://adcontextprotocol.org/schemas/v3/account/get-account-requests-request.json)
**Response schema:** [`account/get-account-requests-response.json`](https://adcontextprotocol.org/schemas/v3/account/get-account-requests-response.json)

## When to call

- **After `account_request.changed`.** The webhook is an invalidation signal; read the request by `request_id` for its state.
- **Polling** while a request is open and no webhook is registered. Back off: seller review often takes hours or days.
- **Cold start.** Read open requests (`in_review`, `ambiguous`) together with [`list_accounts`](/docs/accounts/tasks/list_accounts) to rebuild local state.

## Request

| Field | Required | Description |
| --- | --- | --- |
| `request_ids` | No | Up to 100 IDs. Unknown IDs, and IDs belonging to other callers, are omitted silently. |
| `states` | No | Filter by `in_review`, `resolved`, `ambiguous`, `rejected`. |
| `pagination` | No | Standard pagination. |

With no filters, the seller returns every open request plus requests that changed state in the last 30 days. Sellers retain resolved and rejected requests for at least 30 days after their last state change.

```json
{
  "adcp_version": "3.3",
  "states": ["in_review", "ambiguous"]
}
```

## Response

`requests[]` holds [account request](https://adcontextprotocol.org/schemas/v3/core/account-request-record.json) objects, newest `updated_at` first.

```json
{
  "status": "completed",
  "requests": [
    {
      "request_id": "areq_01K4F8M2Q7",
      "state": "in_review",
      "requested": {
        "brand": { "domain": "renault.fr", "countries": ["FR"] },
        "operator": "wppmedia.fr",
        "currency": "EUR",
        "billing": "operator"
      },
      "pending_action": {
        "waiting_on": "buyer",
        "kind": "sign_up",
        "url": "https://advertisers.streamhaus.example/register?ref=areq_01K4F8M2Q7",
        "message": "No existing relationship found. Register WPP Media France as an advertiser.",
        "expires_at": "2026-11-15T00:00:00Z"
      },
      "created_at": "2026-10-18T09:00:00Z",
      "updated_at": "2026-10-19T10:12:00Z"
    }
  ]
}
```

## The `account_request.changed` webhook

Sellers that declare `account.requests.event_type` fire `account_request.changed` to caller-scoped subscribers on every seller-driven transition: review finishing, a buyer action being required or completed, a match, or an expiry. Register for it in the caller-scoped `notification_configs` of [`sync_principal`](/docs/protocol/sync_principal) or [`sync_agent_notification_configs`](/docs/protocol/sync_agent_notification_configs). Accounts don't exist yet, so account-level `notification_configs` can't carry it.

The payload ([`core/account-request-changed-webhook.json`](https://adcontextprotocol.org/schemas/v3/core/account-request-changed-webhook.json)) carries `request_id`, `previous_state`, and `state`. It is not authoritative: re-read the request here.
