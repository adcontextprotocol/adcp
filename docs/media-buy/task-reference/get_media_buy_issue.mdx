`get_media_buy_issue` synchronously returns the latest seller-owned snapshot
of one issue created by
[`report_media_buy_issue`](/docs/media-buy/task-reference/report_media_buy_issue).
It requires `media_buy.issue_reporting: true`. Poll this task with bounded
backoff to observe human acknowledgement and terminal resolution; an automated
`reported` receipt is not human acknowledgement. Poll sequentially so an older
in-flight response cannot overwrite a newer observation.

**Request schema:** [get-media-buy-issue-request.json](https://adcontextprotocol.org/schemas/latest/media-buy/get-media-buy-issue-request.json)

```json
{
  "$schema": "https://adcontextprotocol.org/schemas/latest/media-buy/get-media-buy-issue-request.json",
  "account": { "account_id": "account_123" },
  "media_buy_id": "media_buy_789",
  "issue_id": "issue_123"
}
```

**Response schema:** [get-media-buy-issue-response.json](https://adcontextprotocol.org/schemas/latest/media-buy/get-media-buy-issue-response.json)

A successful response has `outcome: "found"` and carries the current `issue`.
A failure has `outcome: "failed"` and carries `errors[]`, never `issue`.
`reported` has no acknowledgement or resolution fields. `acknowledged` requires
`acknowledged_at`. `resolved` additionally requires `resolved_at` and a
`resolution` summary. Resolution can explain why no seller change was warranted;
it does not assert buyer agreement or settle a delivery dispute.

The seller authorizes every read against the selected account and media buy.
An issue ID alone conveys no authority. Unknown, mismatched, and inaccessible
identifiers use the same [`REFERENCE_NOT_FOUND`](/docs/building/verification/compliance-catalog#error-code-reference-not-found) response. Reads never mutate
report state or restart the response clock. Sellers MUST keep open reports
readable after the buy is paused, canceled, or completed. This polling contract
does not imply a webhook subscription.
