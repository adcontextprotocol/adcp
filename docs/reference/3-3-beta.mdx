# AdCP 3.3 prerelease history

<Info>
**AdCP 3.3 is generally available** as release `3.3.0` (published 2026-12-03), wire pin `"3.3"`. Move integrations pinned to a 3.3 beta or release candidate to `"3.3"` and to the stable SDKs: TypeScript `@adcp/sdk@17.0.0` and, once it is published, Python `adcp==10.0.0`. Start with [What's new in AdCP 3.3](/docs/reference/whats-new-in-3-3) and [Migrating from 3.2 to 3.3](/docs/reference/migration/3-2-to-3-3).
</Info>

This page is the record of the 3.3 prerelease cycle. Every published prerelease remains an immutable, signed checkpoint, so adopters who pinned one can still reproduce and debug their results.

## Changes between rc.3 and 3.3.0

Adopters moving from `3.3.0-rc.3` to `3.3.0` should check these changes, which landed during the GA freeze:

- **A repeated `format_kind` needs `format_option_ref` ([#8876](https://github.com/adcontextprotocol/adcp/pull/8876)).** When two or more of the target product's `format_options` share a creative manifest's `format_kind`, a seller MUST reject a manifest without `format_option_ref`, and MUST NOT infer the option from which declaration the assets fit. The `media_buy_seller/canonical_formats` storyboard (1.2.0) checks it, gated on `media_buy.features.inline_creative_management`.
- **Bundled schemas ([#9167](https://github.com/adcontextprotocol/adcp/pull/9167)).** `/schemas/{version}/bundled/` keeps each field's own `description`, `default`, `deprecated`, and `x-*` annotations when the build hoists a repeated enum to root `$defs`, and hoists inside `definitions` entries too, so 29 of 124 bundles shrink. Source schemas and validation are unchanged, but a generator that reads bundled annotations may produce different comments or defaults.

The wire pin moves from `"3.3-rc.3"` to `"3.3"`. A release pin never resolves onto a prerelease, so a peer that still advertises only `"3.3-rc.3"` must list `"3.3"` before stable 3.3 buyers can reach it.

Each SDK prerelease negotiates only the prerelease it bundles, so a buyer and seller on different checkpoints settle on a stable release. The per-checkpoint detail is in the [release notes](/docs/reference/release-notes#prerelease-checkpoints) and in `CHANGELOG.md`.

## Version strings

The artifact version, wire pin, and documentation selector are related but not interchangeable:

| Surface | Betas | Release candidates | GA |
|---|---|---|---|
| Protocol artifact | `3.3.0-beta.N` | `3.3.0-rc.N` | `3.3.0` |
| Git tag | `v3.3.0-beta.N` | `v3.3.0-rc.N` | `v3.3.0` |
| `adcp_version` wire pin | `"3.3-beta.N"` | `"3.3-rc.N"` | `"3.3"` |
| Documentation selector | `3.3-beta` (frozen at beta.5) | `3.3-rc` (frozen at rc.3) | `3.3` |

Prerelease pins are exact. A buyer pinned to `"3.3-rc.3"` never silently negotiates to another prerelease, and a stable `"3.3"` pin never resolves onto a prerelease. If you keep running a pinned prerelease compliance bundle for regression evidence, run it against a staging endpoint. Do not weaken production authentication to accommodate a prerelease runner.

During the cycle the public test agent served an opt-in preview of the 3.3 prerelease that the current `@adcp/sdk` prerelease negotiated: `3.3-beta.6`, then `3.3-rc.0`, then `3.3-rc.3`. A release pin never reached the preview. Once the test agent moves to the `3.3.0` bundle, it serves `"3.3"` as a stable release. No 3.3 badge was issued from a prerelease run.

## What left 3.3 during the prereleases

### Withdrawn after beta.1

Three features shipped in `3.3.0-beta.1` and are not part of 3.3. All three add terms to `commercial_terms`, which is held closed until 4.0 ([adcp#8501](https://github.com/adcontextprotocol/adcp/issues/8501)). They are planned for 4.0, where `commercial_terms` gets a declared extension point with must-understand.

| Feature | Shipped in | Action |
|---|---|---|
| Definition pins: `commercial_terms.definition_pins[]`, the `definition_changed` reason, `drifted_pins[]`, `REFERENCE_DEFINITION_CHANGED`, the `definition_pin_probe` scenario, and the `definition_pin_drift` storyboard ([#7960](https://github.com/adcontextprotocol/adcp/pull/7960)) | beta.0 and beta.1 | Stop emitting and requiring them. The beta rule that sellers pin covered definitions no longer applies. |
| Purchase rights (`media_buy.purchase_rights`): `purchases[].rights[]`, `brand/rights-scope.json`, and the `paid_amplification` and `content_reuse` values of `right-use` ([#8101](https://github.com/adcontextprotocol/adcp/pull/8101)) | beta.1 | Stop listing the feature id and emitting `rights[]`. Carry rights through `acquire_rights` until 4.0. |
| Installment selection (`media_buy.installment_selection`): `purchases[].installments[]` and `refine_proposals` `installment_changes` ([#8246](https://github.com/adcontextprotocol/adcp/pull/8246)) | beta.1 | Stop listing the feature id and emitting or accepting the fields. Installments on the canonical product and `holds[]` stay. beta.6 brings back the request side as experimental `media_buy.installment_refinement` (#8974); `purchases[].installments[]` stays planned for 4.0. |

### Closed-schema triage at beta.6

On 2026-11-09 the working group decided that 3.x opens the schemas that were closed by accident ([DR-0036](https://github.com/adcontextprotocol/adcp/blob/main/governance/decisions/DR-0036-closed-schemas-stay-closed-within-a-major.md)). The [#8501](https://github.com/adcontextprotocol/adcp/issues/8501) triage then re-checked every beta feature that had been withdrawn because its schema was closed. A feature withdrawn only for that reason stays in 3.3. Two reasons still remove a field: it sits on a deprecated task or row, or it would extend a schema held closed until 4.0. The [migration guide](/docs/reference/migration/3-2-to-3-3#closed-schema-triage-what-stays-in-3-3) lists every field, and what to do if you built from a beta.

| | Fields | Why |
|---|---|---|
| **Stays in 3.3** | `review_sla` on media-buy actions; minute dayparts and `time_granularity`; the spot-lifecycle capability fields; `collection_lists`; core gender targeting; `trackers` and `landing_page_url` on `assign` operations; `forced.proposal_id` and `arm: unable` on the test controller; `signing_profile` on notification configs | Their schemas open, so the withdrawal is moot |
| **Leaves 3.3** | Assignment `trackers` and `landing_page_url` on `sync_creatives` `assignments[]` and on package creative assignments; on `get_products`, `refine[].package`, the `refinement_applied[]` additions, `filters.target_audiences`, and `include_collections` with `collections`; on `create_media_buy` and `update_media_buy`, `predecessor_media_buy_id` and `lineage_reason`, `artifact_webhook.signing_profile`, `target_audiences`, and `start_requires_all_creatives_approved` | Deprecated surface. The live tasks keep these features where they already carry them: `assignment_operations`, `list_products`, `buy_products` and `accept_proposal`, and `control_media_buy` |
| **Moves within 3.3** | `execution_readiness` from `get_products` to `list_products`; `clock` and `business_calendar_id` from `sla-window` to the creative-review SLA; `available_installment_statuses` to the canonical reporting capabilities | The old home is deprecated or held closed until 4.0 |
| **Planned for 4.0** | `price_adjustments` (`media_buy.price_adjustments`); `counting_mechanisms` on measurement terms; `target_audiences` on purchases | The legacy copy sits on a deprecated surface, and the canonical copy would extend the commercial terms, which are held closed until 4.0 |

### Renamed at rc.0

Three experimental values took the spelling their stable or sibling counterpart already uses, with no alias ([#8989](https://github.com/adcontextprotocol/adcp/pull/8989)): `input_required` → `input-required` (`media_buy.execution_readiness`), `click_through` → `clickthrough` (`creative.live_updates`), and `underdelivery` → `under_delivery` (`media_buy.delivery_projection`).

### Withdrawn after rc.0

`metric_id` on performance standards and `required_performance_standards` ([#8436](https://github.com/adcontextprotocol/adcp/pull/8436)) shipped in beta.1 through rc.0 and is withdrawn by [#8854](https://github.com/adcontextprotocol/adcp/pull/8854), first published in rc.2. The canonical performance standard is part of the signed commercial terms, which are held closed until 4.0, so the field is planned for 4.0. The same change restores `evaluator` as a deprecated `x-entity-types` value, which beta.0 had removed.

The designs of every withdrawn feature are kept in [Planned for 4.0](/docs/reference/migration/v4-compatibility#planned-for-4-0-withdrawn-from-3-3).

## Decisions recorded in the 3.3 cycle

| Decision | What it changes |
|---|---|
| Agent identity is an origin ([DR-0023](https://github.com/adcontextprotocol/adcp/blob/main/governance/decisions/DR-0023-agent-identity-is-an-origin.md)) | Agents are identified by origin and sign HTTP requests and webhooks with the Web Bot Auth profile; the RFC 9421 brand.json profile is deprecated in 3.3 and removed in 4.0. |
| Responses conform to the served release ([DR-0024](https://github.com/adcontextprotocol/adcp/blob/main/governance/decisions/DR-0024-responses-conform-to-served-release.md)) | Every response validates against the release the seller served, including `get_adcp_capabilities` and webhook payloads. |
| Demand-side grants ([DR-0025](https://github.com/adcontextprotocol/adcp/blob/main/governance/decisions/DR-0025-demand-side-grants-in-trust-json.md)) | An operator declares in trust.json which agents may act for it, and sellers report `grant_absent`. |
| JWS artifacts use the Web Bot Auth key directory ([DR-0026](https://github.com/adcontextprotocol/adcp/blob/main/governance/decisions/DR-0026-jws-artifacts-use-the-wba-key-directory.md)) | Governance contexts, designated-task response signatures, and rights attestations from an origin its trust record lists verify against that origin's key directory; amends DR-0023. |
| `error.mutation_outcome`, `sales-fixed-rate`, delivery projection, and media-buy lineage ([DR-0027](https://github.com/adcontextprotocol/adcp/blob/main/governance/decisions/DR-0027-mutation-outcome-on-error.md) to [DR-0030](https://github.com/adcontextprotocol/adcp/blob/main/governance/decisions/DR-0030-media-buy-lineage-forward-only.md)) | Record the surfaces merged for beta.0. `sales-fixed-rate` is stable from beta.5. |
| Seller revisions advance on every committed change ([DR-0031](https://github.com/adcontextprotocol/adcp/blob/main/governance/decisions/DR-0031-seller-revision-any-origin.md)) | A seller-maintained revision advances on every committed change, whatever its origin; the `sync_creatives` assignment carve-out is removed. Other resource families are deferred to a later release. |
| A major-only request is served the oldest supported release ([DR-0034](https://github.com/adcontextprotocol/adcp/blob/main/governance/decisions/DR-0034-major-only-requests-are-served-the-oldest-release.md)) | A request that carries `adcp_major_version` and no `adcp_version` is served the oldest release the seller supports in that major, 3.0 where supported. `adcp_major_version` is removed in 4.0 ([DR-0035](https://github.com/adcontextprotocol/adcp/blob/main/governance/decisions/DR-0035-adcp-major-version-removed-in-4-0.md)). |
| Schemas are open by default ([DR-0036](https://github.com/adcontextprotocol/adcp/blob/main/governance/decisions/DR-0036-closed-schemas-stay-closed-within-a-major.md)) | A schema stays closed only for a structural reason, and `commercial_terms` is held closed until 4.0. A minor adds to open schemas and adds nothing to closed ones. |
| Verifiers bundle the Public Suffix List ([DR-0037](https://github.com/adcontextprotocol/adcp/blob/main/governance/decisions/DR-0037-psl-bundled-not-pinned.md)) | Verifiers compute eTLD+1 with a list bundled with the verifier, never fetched at runtime. |

Proposals that did not merge before the GA freeze are not part of 3.3. Most moved to the 4.0 and 4.x milestones; see the [open milestones](https://github.com/adcontextprotocol/adcp/milestones?state=open).

## Artifact retention

Published prerelease artifacts are never retired or rebuilt: the signed protocol tarball, schemas, and compliance bundle of every 3.3 beta and release candidate stay at their versioned URLs. `3.3.0-rc.1` was never published, and nothing serves it as a release. The `3.3-beta` and `3.3-rc` documentation snapshots stay reachable by URL after their selectors leave the version picker. To reproduce a pinned checkpoint, download its tarball and verify it as described in [Verifying protocol tarballs](/docs/reference/verifying-protocol-tarballs):

```bash
curl -fLO https://adcontextprotocol.org/protocol/3.3.0-rc.3.tgz
curl -fLO https://adcontextprotocol.org/protocol/3.3.0-rc.3.tgz.sha256
shasum -a 256 -c 3.3.0-rc.3.tgz.sha256
```
